# Product UI

Operate layout primary for Remedy. The public repo `kuras3/product-ui-design` returns 404. This file is the local source. Do not clone that URL.

Build the screen a person uses every day. Scanability and the real task outrank expression. Brand lives in precise details.

## Before markup

1. Name the anchor and the diverge in a file-top comment: `/* anchor: <product or DNA>, diverge: <what changed> */`.
2. Use the project's tokens. Do not invent a second palette.
3. One competent product sans. Hierarchy from weight, size, and muted color.

Pick one anchor and change one thing. Examples: Linear-dense with a warmer accent, Stripe-like tables, an airier shell. Do not dress a dashboard as a campaign.

## Floor

- No film grain, radial glow, custom cursor, parallax, or hero theater.
- No purple-blue accent family and no purple glow.
- No glowing or pulsing status dots. A flat dot plus a word.
- No monospace on labels, eyebrows, or section numbers. Mono is for code and data.
- No reflexive filled-plus-ghost CTA pair.
- No four equal KPI cells unless the numbers are true peers.
- No pure `#000` text or background, and no single-layer pure-black shadow.
- No editorial-dashboard costume: serif greeting, cream paper, tracked kickers, oldstyle figures in stat cells.
- No tasteful-terminal costume: mono on chrome, ASCII as the product look.
- A view that can be empty or failed has an empty state and an error state.
